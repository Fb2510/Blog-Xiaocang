macOS 使用 Clash Verge Rev：芯片版本、系统代理与 DNS 恢复

小仓2026-09-29— 次阅读
客户端教程

Mac 上的代理故障经常与当前网络服务、系统代理和 DNS 状态有关。安装成功但 Safari 不联网，或退出客户端后仍然无法打开网页，不能仅靠换节点判断原因。

本文以 Clash Verge Rev 为例，重点说明 macOS 的安装与恢复。Windows 用户可阅读Windows 使用教程。

核对 Intel 与 Apple 芯片版本

在“关于本机”查看芯片和 macOS 版本，再从官方安装页面选择匹配的发布文件。系统最低版本要求会变化，不要只凭“可以下载”判断当前系统受支持。

遇到无法打开或来源验证提示，应先确认下载来源、文件完整性和官方说明。Apple 提供了安全打开应用的处理方法；不要复制来源不明的命令，把整个系统的安全检查长期关闭。来源：Apple 应用安全说明

导入配置后做最小测试

添加服务商提供的兼容订阅，启用配置并选择一个节点。第一次先使用系统代理，打开一个 HTTPS 页面，同时查看客户端连接记录。确认浏览器请求进入了预期策略组之后，再增加自定义规则或其他接入功能。

如果订阅仅能下载而解析失败，检查是否拿到了 Clash/Mihomo 配置。格式问题与节点是否到期属于不同环节，处理路径见订阅失败排查。

系统代理设置要看当前网络服务

在较新的 macOS 中，可从系统设置进入“网络”，选择正在使用的网络服务，打开“详细信息”中的“代理”。Apple 文档列出了 HTTP、HTTPS、SOCKS 和自动代理配置等项目。来源：Mac 代理设置

Wi-Fi 与有线网络是不同服务。换成扩展坞网线后出现异常时，应检查新服务的状态，而不是只查看原来的 Wi-Fi 项目。企业设备上的受管理设置应由管理员核对，不要直接覆盖。

两条只读命令帮助记录状态

终端中运行：

scutil --proxy
scutil --dns

第一条显示代理相关信息，第二条显示解析器配置。输出可以帮助比较启用前、启用后和退出后的变化，但它们不证明具体应用一定经过代理。分享时注意其中可能含内部域名、网络地址或自动配置地址。

把结果与客户端中的监听端口、TUN 状态一起看。端口仍指向本地但客户端已经退出，是一种可排查的原因；不要因为看到多个解析器就断言 DNS 泄露。

启用 TUN 前记录 DNS

Clash Verge Rev 的 macOS FAQ 说明，启用 TUN 时可能调整系统 DNS，正常关闭时应恢复。客户端与内核版本不同可能改变具体行为，因此应先记录原配置，再观察实际变化。来源：官方 macOS FAQ

如果 TUN 后局域网服务异常，先关闭 TUN 做对照，再分别检查局域网访问规则与 DNS。不要为了测试直接清空公司网络或固定 IP 配置。

退出后无法联网的恢复顺序

先正常关闭代理及 TUN，并退出客户端；随后检查当前网络服务中的代理是否仍指向停止的本地端口。恢复到启用前记录的状态，再检查 DNS 是否一致。

如果手动设置过 DNS，恢复的是你自己的原配置，不是从教程随便找一组公共地址。完成后测试普通网页、局域网资源和目标应用。仍有问题再重新启动客户端收集日志，参照DNS 与 Fake-IP 排查逐层定位。

资料核对：2026 年 9 月 28 日。命令用于读取状态，不会自动修改网络设置。
